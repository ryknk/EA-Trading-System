# 取引

## 注文管理

注文管理コンポーネント（Order Manager）は戦略判断を行わず、シグナル候補、外部`ALLOW`、最新のRisk承認、正の取引数量、取引変更許可設定がすべて揃った場合だけ要求を組み立てる。送信直前に最新ティックを取得し、`OrderCheck`を再実行する。バー時刻を口座・マジックナンバー・シンボル別のターミナルグローバル変数へ送信前に保存し、結果が曖昧でも同じバーを自動再送しない。

成行要求にはマジックナンバー、シンボル、数量、方向、価格、SL、TP、許容偏差、ブローカー対応の約定方式、候補ID由来のコメントを設定する。`DONE`、`PLACED`、`DONE_PARTIAL`だけを承認済みとして扱う。部分約定の残量は自動追撃せず、取引イベントで事実を確認する。即時結果として要求価格・確認価格、数量、スリッページ、注文・約定チケット、戻り値を記録する。

Phase 4ではControllerの`external_approved`がコンパイル時定数falseのため、新規`OrderSend`へ到達しない。Phase 5/6でも有効期限、要求ID、スキーマ、ML/LLM判断を検証できるまではfalseを維持する。

## ポジション管理

`OnTick`の最初に、設定したマジックナンバーと一致する全シンボルのポジションを監視する。正常な保護SLがない、またはギャップ等で現在価格がSLを越えたポジションは無保護とし、Risk Managerの運用健全性をfalseにして新規注文を停止する。

`enable_trade_mutations=true`かつ`close_unprotected_positions=true`の場合、無保護ポジションを反対売買で全量決済する。これは外部APIに依存しないリスク削減経路である。決済要求も`OrderCheck`し、ポジションチケット付きで送る。送信前にチケット単位のターミナルグローバル変数を保存し、曖昧な失敗や再起動後に同じポジションへ自動再送しない。成功確認前も新規注文は禁止する。

`OnTradeTransaction`でEAのマジックナンバーに一致する約定だけを選別し、エントリー種別、シンボル、価格、数量、損益、手数料、スワップ、追加費用をログ出力する。正式な永続監査ロガーはPhase 9で追加する。
